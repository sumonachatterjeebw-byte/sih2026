# Trained models: what, on what data, and how we know

This document answers the question a judge will ask: *what did you actually train, on what, and
how do you know it works?* Every figure here comes from `models/metrics.json`, which is written
by `python -m scripts.train` and committed to the repository so the numbers can be checked
against the code that produced them.

**One command trains everything:**

```bash
python -m scripts.train           # full run, about 4 minutes on a laptop CPU
python -m scripts.train --quick   # fast smoke run
```

---

## The honesty statement, up front

**The training data is generated by this repository's own physics environment**, not by
satellites. `src/core/environment.py`, `src/core/sea_ice.py` and `src/core/iceberg_tracker.py`
stand in for ERA5/CMEMS forcing, OSI-SAF/AMSR2 concentration and USNIC/BYU iceberg tracks.

Everything below is therefore **simulated-environment skill and must never be presented as
operational forecast skill.** What it demonstrates is that the pipeline is real and complete:
feature extraction, time-based splitting with an embargo, hyperparameter selection on a
validation window, and evaluation against honest baselines on a held-out test window. Pointing
that pipeline at Copernicus data is a data-loader change.

**Two of the three models do not beat the physics they were meant to improve, and are not used
in the serving path.** That is reported here rather than hidden, because a system claiming three
working AI engines when one works is a system nobody should trust with a ship.

### Why splits are time-based, never random

Nearby samples share the same underlying noise field. A random split would put a sample's near
neighbour in the training set and report a score that is mostly memorisation. Splits are
therefore by **time window with an embargo gap**:

| Model | Split rule | Embargo |
| :--- | :--- | :--- |
| SIC forecaster | disjoint `t0` windows; validation 1128–1440 h, test 1608–1992 h | 168 h |
| Drift residual | disjoint bergs *and* disjoint time windows; test 1296–1680 h | by construction |
| Growler classifier | by radar sweep (scene), forward in generation order | by scene |

## 1. Sea-ice concentration forecaster

**Task.** Predict ice concentration at `t0 + lead` from the analysis state at `t0`, for leads of
24, 48, 72, 120 and 168 hours.

**Estimator.** `HistGradientBoostingRegressor` — learning rate 0.06, 400 iterations, 63 leaf
nodes, minimum 40 samples per leaf, L2 regularisation 1.0. Selected on the validation window
against a second configuration.

**Dataset.** 44,800 training rows, 11,900 validation, 20,300 test; 140 sampled points per scene.

**Features (21).** `concentration`, `dconc_dlat_per_deg`, `dconc_dlon_per_deg`, `latitude`,
`longitude`, `sin_doy`, `cos_doy`, `u10_ms`, `v10_ms`, `wind_speed_ms`, `current_u_ms`,
`current_v_ms`, `t2m_c`, `sst_c`, `drift_u_ms`, `drift_v_ms`, `divergence_per_s`,
`compression_index`, `distance_to_coast_nm`, `ice_edge_lat`, `lead_hours`.

**Baselines.** Persistence (assume nothing changes), climatology, and the project's own
semi-Lagrangian physics forecast.

### Results, held-out test split, RMSE in concentration units

| Lead | Learned | Persistence | Climatology | Physics | Skill vs persistence | Skill vs physics |
| ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 24 h | 0.0610 | **0.0522** | 0.1467 | 0.0573 | −0.167 | −0.063 |
| 48 h | 0.0931 | **0.0859** | 0.1483 | 0.0909 | −0.084 | −0.025 |
| 72 h | 0.1078 | **0.1047** | 0.1472 | 0.1027 | −0.030 | −0.050 |
| 120 h | 0.1198 | 0.1229 | 0.1462 | **0.1116** | **+0.025** | −0.074 |
| 168 h | 0.1294 | 0.1350 | 0.1456 | **0.1159** | **+0.042** | −0.116 |
| **Pooled** | 0.1050 | 0.1043 | 0.1468 | **0.0979** | −0.006 | −0.072 |

**Verdict: not used.** The API serves the physics forecast.

There is a real pattern in that table worth pointing at rather than glossing over. The learned
model **loses to persistence at short leads and beats it at long ones**, crossing over around
100 hours — which is exactly the behaviour you would expect, because at 24 hours the pack has
barely moved and persistence is nearly unbeatable, while at 168 hours there is genuine structure
to learn. But it never overtakes the physics forecast at any lead.

Data volume mattered a great deal: on a `--quick` run with 2,800 rows the model was 22 percent
behind persistence overall; at 44,800 rows it is level with it. It did not, however, change the
ranking against physics.

**Why this is the expected result, not a disappointing one.** The synthetic ice field's patterns
are *generated* by advection. A semi-Lagrangian back-trajectory is therefore close to the exact
inverse of the generating process, and no model fitted to 21 tabular summary features is going to
beat it in its own world. The situation reverses on real satellite rasters, where true ice
dynamics are far richer than any advection scheme captures — which is precisely why the pipeline
is built and kept.

## 2. Iceberg drift residual corrector

**Task.** Learn the velocity error of the physics momentum balance, and add it back as a
correction. This is the module behind the original blueprint's "PINN" claim.

**It is not a physics-informed neural network.** The governing equation is not part of the loss
function. It is a **residual corrector on a physics core**, and calling it a PINN would be a
false claim.

**Estimator.** `MLPRegressor`, selected over Ridge on the validation window (residual RMSE
0.042 m/s against 0.055 m/s).

**Dataset.** 300 training bergs, 90 validation, 140 test — disjoint bergs on disjoint time
windows. 10,800 / 3,240 / 5,040 rows at a 2-hour output interval over 72-hour forecasts.

**Features (11).** `wind_u_ms`, `wind_v_ms`, `current_u_ms`, `current_v_ms`, `length_m`,
`width_m`, `sail_height_m`, `keel_depth_m`, `latitude`, `physics_u_ms`, `physics_v_ms`.
**Targets.** `residual_u_ms`, `residual_v_ms`.

### Results, held-out test split

Residual velocity RMSE improves marginally, 0.0364 → 0.0353 m/s, explaining 6.3 percent of the
residual variance. What matters operationally is 72-hour position error:

| 72-hour position error | Mean | Median | p90 |
| :--- | ---: | ---: | ---: |
| Physics (Euler) | 6.95 km | **3.85 km** | 19.84 km |
| Physics + learned residual | **6.86 km** | 4.35 km | **17.11 km** |
| Physics (RK4, the shipped integrator) | **6.41 km** | **3.48 km** | 17.73 km |

**Verdict: not used.** It improves the mean by 1.3 percent while making the median 12.9 percent
worse, and helps only 45 percent of bergs — a coin flip. Decisively, **the shipped RK4 integrator
on its own (6.41 km) beats the corrected Euler baseline (6.86 km)**, so the correction buys
nothing that better integration does not already provide.

**Why it fails, honestly.** The "observed" tracks are generated by perturbing the *same*
momentum balance the model is correcting. The residual is therefore close to unstructured noise,
with almost no systematic signal to learn. On real USNIC and BYU tracks the physics has genuine
systematic bias — unknown keel geometry, unresolved sub-surface currents, calving and roll — and
a residual learner is a sound approach with real signal to find. Here there is nothing there.

## 3. Growler and sea-clutter classifier

**Task.** Given a radar return, decide whether it is a real ice target or a sea-clutter false
alarm. This is the one that works.

**Estimator.** `RandomForestClassifier` — 300 trees, max depth 14, minimum 3 samples per leaf,
`sqrt` features.

**Dataset.** 1,600 simulated sweeps, 18,268 returns; 10,979 train / 2,853 validation / 4,436
test, split by scene. Positive fraction 0.514, so accuracy is a meaningful metric.

**Features (8), with importances.** `aspect_ratio` (0.459), `blob_area_px` (0.220),
`doppler_ms` (0.131), `rcs_dbsm` (0.057), `sig_wave_height_m` (0.045), `snr_db` (0.040),
`ice_concentration` (0.034), `range_nm` (0.014).

### Results, held-out test split

| Model | Accuracy | Precision | Recall | F1 | ROC-AUC |
| :--- | ---: | ---: | ---: | ---: | ---: |
| Random forest | **0.988** | 0.986 | 0.992 | **0.989** | **0.999** |
| SNR threshold (13.28 dB) | 0.572 | 0.567 | 0.921 | 0.702 | 0.607 |
| Majority class | 0.546 | 0.546 | 1.000 | 0.707 | — |

Confusion matrix: 2,063 true negatives, 33 false positives, 19 false negatives, 2,321 true
positives.

**Verdict: used.** It supplies the detection-confidence value on radar contacts.

**Why it works where the others do not.** Discriminating a small ice target from a clutter spike
is genuinely multivariate: it depends on the *combination* of blob shape, Doppler signature and
sea state. Aspect ratio alone carries 46 percent of the importance, and no single-threshold rule
can use it — which is why the SNR baseline sits at F1 0.70 while the forest reaches 0.99.

Note the 19 false negatives. In this context a missed target is the dangerous error, and the
model is tuned toward recall (0.992) accordingly. It still misses some, and the radar simulation
itself misses far more before the classifier ever sees them — see `src/core/growler_radar.py`.

## How to retrain on real data

The pipeline is deliberately separated from the data source. Replacing the generator in
`src/ml/dataset.py` with a reader for the products below is the whole change.

| Layer | Product | Access |
| :--- | :--- | :--- |
| Sea-ice concentration | OSI SAF **OSI-401-b** global sea-ice concentration, 10 km, daily | EUMETSAT OSI SAF |
| Sea-ice concentration, higher resolution | **AMSR2** ASI 3.125 km | University of Bremen / JAXA GCOM-W1 |
| Sea-ice drift and type | **Sentinel-1** GRD EW-mode SAR | Copernicus Data Space Ecosystem |
| Atmospheric forcing | **ERA5** reanalysis and **HRES** forecasts (`u10`, `v10`, `t2m`, `msl`) | ECMWF / Copernicus CDS |
| Ocean forcing | **GLOBAL_ANALYSISFORECAST_PHY_001_024** (`uo`, `vo`, `thetao`, `siconc`, `sithick`) | Copernicus Marine Service |
| Iceberg tracks | Antarctic iceberg tracking database | US National Ice Center; BYU Center for Remote Sensing |
| Radar returns | Recorded X-band PPI and thermal imagery from an expedition vessel | Requires a field campaign |

Two caveats about that last row. There is no public labelled dataset of radar returns annotated
as ice or clutter, so the growler classifier is the model that most needs real data before any
operational claim could be made. And on real imagery the right architecture is a detector on the
raw PPI rather than a classifier on extracted blob features — the current model assumes a blob
detector has already run.

For the sea-ice forecaster on real rasters, the appropriate model is a convolutional
spatiotemporal network in the IceNet family (Andersson et al., *Nature Communications* 2021),
not a gradient-boosted tree on summary features. That is future work, and it is listed as such
rather than claimed as done.

## Reproducing these numbers

```bash
python -m scripts.train              # regenerates models/ and models/metrics.json
python -m pytest tests/test_ml.py -q # determinism, split disjointness, save/load, bounds
```

Training is seeded (`GLOBAL_SEED = 26059`), so a rerun on the same scikit-learn version
reproduces these figures. `models/metrics.json` records the Python, NumPy and scikit-learn
versions, the split boundaries, the dataset sizes, the feature names and the wall-clock time.

The `models/*.joblib` artefacts are not committed — they total about 13 MB and are regenerable
by the command above. `models/metrics.json` **is** committed, so every number in this document
can be checked without retraining. The system degrades gracefully when the artefacts are absent:
`/api/v1/health` reports which models are available, and the physics path never depends on any
of them.
